# Exercise: evaluate a RAG chain with MLflow

**Scenario (certification style).** The claims team wants to ship prompt `v2` of their policy Q&A chain. Before approving, the tech lead asks for evidence: "Show me v2 is at least as correct and grounded as v1, that it cites sources, and that it stays inside the latency budget. Use MLflow so we can compare runs later."

You will trace a small RAG chain, evaluate two prompt versions with `mlflow.genai.evaluate` using built-in LLM judges, one `Guidelines` scorer and two custom code scorers, compare the runs and write a recommendation.

Works on **local MLflow** (`mlflow ui` or `mlflow server`) with Anthropic or OpenAI as the app and judge model, or on **Databricks** with serving endpoints.

**Time:** 75–90 minutes.

<Callout type="warning" title="MLflow versions">

This exercise uses the MLflow 3 GenAI API (`mlflow.genai.evaluate`, `mlflow.genai.scorers`). If you are on MLflow 2, upgrade, or adapt to `mlflow.evaluate(..., model_type="databricks-agent")` on Databricks. Judge model URI formats depend on the MLflow version; check mlflow.org/docs.

</Callout>

## Tasks

- **Task 1 — Dataset.** Take 25 records from `01-sql-llm-logs/data/eval_v1.jsonl` (or write your own against the documents from exercise 10). Label each one: add `expected_facts` (1–3 short facts) in `expectations`. Save as `data/eval_labeled_v1.jsonl`. Include at least 3 questions the documents **cannot** answer, with the expected fact "The assistant says it does not have enough information".
- **Task 2 — Chain + tracing.** Implement `answer(question, prompt_version)` using the retriever from exercise 10 (or the tiny in-memory retriever below). Trace with autolog for your LLM SDK plus `@mlflow.trace(span_type=SpanType.RETRIEVER)` on retrieval.
- **Task 3 — Scorers.** Use `Correctness`, `RelevanceToQuery`, `RetrievalGroundedness`, `Safety`, one `Guidelines` scorer (domain rule of your choice) and two code scorers: `has_citation` and `latency_budget` (3 s).
- **Task 4 — Compare.** Run the evaluation once per prompt version as two MLflow runs with params `prompt_version`, `dataset_version`, `judge_model`, `app_model`. Produce a comparison table and inspect at least 3 rows where the versions disagree.
- **Task 5 — Judge sanity check.** Hand-label `Correctness` on 10 rows yourself and report agreement with the judge.

```python
# rag_chain.py
import os
import time

import anthropic
import mlflow
from mlflow.entities import SpanType

mlflow.anthropic.autolog()
client = anthropic.Anthropic()
APP_MODEL = os.environ.get("APP_MODEL", "claude-haiku-5-5")

PROMPTS = {
    "v1": "Answer the question using the context.",
    "v2": ("Answer only from the context. Cite each claim as [doc_id]. "
           "If the context does not contain the answer, say you do not have enough information."),
}

@mlflow.trace(span_type=SpanType.RETRIEVER)
def retrieve(question: str, k: int = 4) -> list[dict]:
    from retriever import search          # exercise 10 retriever, or the in-memory fallback
    return [{"page_content": h.content, "metadata": {"doc_uri": h.doc_id, "chunk_id": h.chunk_id}}
            for h in search(question, k=k)]

@mlflow.trace
def answer(question: str, prompt_version: str = "v1") -> str:
    docs = retrieve(question)
    context = "\n\n".join(f"[{d['metadata']['doc_uri']}] {d['page_content']}" for d in docs)
    msg = client.messages.create(
        model=APP_MODEL,
        max_tokens=400,
        system=PROMPTS[prompt_version],
        messages=[{"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"}],
    )
    return msg.content[0].text
```
