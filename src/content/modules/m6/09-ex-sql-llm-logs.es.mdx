# Ejercicio: analiza logs de requests de LLM con SQL y crea un dataset de evaluación

**Escenario (estilo certificación).** Te unes al equipo de plataforma de IA de una aseguradora. Su asistente de reclamos lleva un mes en producción. Producto dice "la calidad bajó después del último cambio de prompt" y finanzas dice "los costos subieron". Tienes una tabla de logs de requests. Responde ambas inquietudes con SQL y luego convierte los logs en un dataset de evaluación versionado y sin PII que usarán los dos ejercicios siguientes.

Puedes hacerlo en **PostgreSQL** (Docker, recomendado si no tienes workspace) o en **Databricks SQL** (Free Edition sirve). El código inicial apunta a Postgres; las notas para Databricks están en las pistas.

**Tiempo:** 60–75 minutos.

## Tareas

- **Tarea 1 — Latencia.** Latencia p50 y p95 por modelo y por día para requests exitosos.
- **Tarea 2 — Costo.** Costo total y costo por cada 1k requests por tenant en los últimos 30 días, los 5 tenants principales.
- **Tarea 3 — Confiabilidad.** Tasa de error (cualquier status distinto de `ok`) por `prompt_version`, con conteo de requests.
- **Tarea 4 — Regresión.** Compara `v7` vs `v8` del prompt en tasa de thumbs-down y tasa de respuestas sin citas, **por ruta**, y marca las rutas donde `v8` es peor por más de 5 puntos porcentuales.
- **Tarea 5 — Dataset de evaluación.** Construye una muestra estratificada: por ruta, 14 ejemplos normales y 6 de falla (falla = thumbs-down, status distinto de ok o cero citas), deduplicada por pregunta normalizada, sin PII, exportada como JSONL con `inputs` / `expectations` / `tags`, más un manifiesto.

<AcceptanceCriteria>

- [ ] `docker compose up` levanta Postgres y `python seed.py` carga al menos 20,000 filas sintéticas con 3 modelos, 2 versiones de prompt, 4 rutas y más de 10 tenants
- [ ] Cada tarea tiene su propio archivo en `sql/` (`01_latency.sql` … `05_eval_sample.sql`) que corre sin modificaciones
- [ ] La Tarea 1 usa percentiles, no promedios; los requests fallidos se excluyen
- [ ] La Tarea 4 usa CTEs y devuelve una fila por ruta con las tasas de ambas versiones, el delta y una columna booleana `regressed`
- [ ] Salida de la Tarea 5: `data/eval_v1.jsonl` con 60–80 registros, sin preguntas normalizadas duplicadas y sin emails ni teléfonos (verificado por un test)
- [ ] `data/eval_v1.manifest.json` registra el archivo de consulta, el rango de fechas, el número de filas, la semilla y la versión del scrubber
- [ ] `pytest` pasa: al menos un test para el scrubber y uno para las invariantes del dataset
- [ ] El README incluye las respuestas a las Tareas 1–4 como tablas pequeñas y dos frases de interpretación para cada una

</AcceptanceCriteria>

```python
# seed.py — synthetic LLM request logs (deterministic)
import json
import random
import uuid
from datetime import datetime, timedelta, timezone

import psycopg

random.seed(42)
MODELS = {"model-small": 0.4, "model-medium": 1.0, "model-large": 3.0}  # relative cost units
ROUTES = ["coverage", "claims_status", "billing", "documents"]
QUESTIONS = {
    "coverage": ["Is water damage from a burst pipe covered?", "Does my policy cover mold?"],
    "claims_status": ["What is the status of claim {n}?", "When will my claim be paid?"],
    "billing": ["Why did my premium go up?", "Can I pay monthly?"],
    "documents": ["Which documents do I need for a theft claim?", "Where do I upload photos?"],
}
PII_SUFFIX = [" My email is jane.doe{n}@example.com", " Call me at 555-01{n:02d}", ""]

def row(i: int, start: datetime) -> tuple:
    route = random.choice(ROUTES)
    version = "v7" if i % 2 == 0 else "v8"
    model = random.choices(list(MODELS), weights=[5, 3, 1])[0]
    q = random.choice(QUESTIONS[route]).format(n=random.randint(1000, 9999))
    q += random.choice(PII_SUFFIX).format(n=random.randint(0, 99))
    bad = version == "v8" and route == "coverage" and random.random() < 0.25
    status = random.choices(["ok", "error", "timeout"], weights=[95, 3, 2])[0]
    cites = [] if bad or random.random() < 0.08 else [{"doc_id": f"POL-{random.randint(1, 40)}"}]
    inp, out = random.randint(300, 4000), random.randint(50, 600)
    cost = (inp + 3 * out) / 1_000_000 * MODELS[model]
    feedback = -1 if bad and random.random() < 0.6 else random.choice([1, None, None, -1 if random.random() < 0.05 else None])
    return (uuid.uuid4(), start + timedelta(minutes=i * 2), f"tenant-{random.randint(1, 12):02d}", model,
            version, inp, out, int(random.lognormvariate(7.2, 0.5)), status, round(cost, 6),
            json.dumps({"question": q, "route": route, "retries": random.choice([0, 0, 0, 1, 2])}),
            json.dumps({"answer": "...", "citations": cites}), feedback)

if __name__ == "__main__":
    start = datetime.now(timezone.utc) - timedelta(days=30)
    with psycopg.connect("postgresql://postgres:postgres@localhost/llmlogs") as conn:
        conn.execute(open("sql/00_schema.sql").read())
        with conn.cursor() as cur:
            cur.executemany("INSERT INTO llm_requests VALUES (%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s)",
                            [row(i, start) for i in range(21_600)])
```

<Hint>Tarea 4: un CTE calcula las tasas por `(route, prompt_version)`; un segundo pivotea con `max(rate) FILTER (WHERE prompt_version = 'v8')` y lo mismo para `v7`. El bug sembrado vive en la ruta `coverage`, así que esa es la fila que deberías ver marcada.</Hint>

<Hint>Tarea 5: calcula `qhash` sobre la pregunta normalizada, usa `DISTINCT ON (qhash)` ordenado para que ganen las fallas y luego `row_number() OVER (PARTITION BY route, bucket ORDER BY random())`.
