# Exercise: analyze LLM request logs with SQL and build an eval dataset

**Scenario (certification style).** You join the AI platform team at an insurance company. Their claims assistant has been in production for a month. Product says "quality dropped after the last prompt change" and finance says "costs are up". You have one table of request logs. Answer both concerns with SQL, then turn the logs into a versioned, PII-scrubbed evaluation dataset that the next two exercises will use.

You can do this on **PostgreSQL** (Docker, recommended if you have no workspace) or on **Databricks SQL** (Free Edition works). The starter code targets Postgres; Databricks notes are in the hints.

**Time:** 60–75 minutes.

## Tasks

- **Task 1 — Latency.** p50 and p95 latency per model per day for successful requests.
- **Task 2 — Cost.** Total cost and cost per 1k requests per tenant for the last 30 days, top 5 tenants.
- **Task 3 — Reliability.** Error rate (any status other than `ok`) per `prompt_version`, with request counts.
- **Task 4 — Regression.** Compare `v7` vs `v8` of the prompt on thumbs-down rate and no-citation rate, **per route**, and flag routes where `v8` is worse by more than 5 percentage points.
- **Task 5 — Eval dataset.** Build a stratified sample: per route, 14 normal and 6 failure examples (failure = thumbs-down, non-ok status, or zero citations), deduplicated on normalized question, PII-scrubbed, exported as JSONL with `inputs` / `expectations` / `tags`, plus a manifest.

<AcceptanceCriteria>

- [ ] `docker compose up` starts Postgres and `python seed.py` loads at least 20,000 synthetic rows across 3 models, 2 prompt versions, 4 routes and 10+ tenants
- [ ] Each task has its own file in `sql/` (`01_latency.sql` … `05_eval_sample.sql`) that runs without edits
- [ ] Task 1 uses percentiles, not averages; failed requests are excluded
- [ ] Task 4 uses CTEs and returns one row per route with both versions' rates, the delta and a boolean `regressed` column
- [ ] Task 5 output: `data/eval_v1.jsonl` with 60–80 records, no duplicate normalized questions, and zero emails or phone numbers (verified by a test)
- [ ] `data/eval_v1.manifest.json` records the query file, date range, row count, seed and scrubber version
- [ ] `pytest` passes: at least one test for the scrubber and one for dataset invariants
- [ ] README includes the answers to Tasks 1–4 as small tables and two sentences of interpretation each

</AcceptanceCriteria>

```python
# seed.py — synthetic LLM request logs (deterministic)
import json
import random
import uuid
from datetime import datetime, timedelta, timezone

import psycopg

random.seed(42)
MODELS = {"model-small": 0.4, "model-medium": 1.0, "model-large": 3.0}  # relative cost units
ROUTES = ["coverage", "claims_status", "billing", "documents"]
QUESTIONS = {
    "coverage": ["Is water damage from a burst pipe covered?", "Does my policy cover mold?"],
    "claims_status": ["What is the status of claim {n}?", "When will my claim be paid?"],
    "billing": ["Why did my premium go up?", "Can I pay monthly?"],
    "documents": ["Which documents do I need for a theft claim?", "Where do I upload photos?"],
}
PII_SUFFIX = [" My email is jane.doe{n}@example.com", " Call me at 555-01{n:02d}", ""]

def row(i: int, start: datetime) -> tuple:
    route = random.choice(ROUTES)
    version = "v7" if i % 2 == 0 else "v8"
    model = random.choices(list(MODELS), weights=[5, 3, 1])[0]
    q = random.choice(QUESTIONS[route]).format(n=random.randint(1000, 9999))
    q += random.choice(PII_SUFFIX).format(n=random.randint(0, 99))
    bad = version == "v8" and route == "coverage" and random.random() < 0.25
    status = random.choices(["ok", "error", "timeout"], weights=[95, 3, 2])[0]
    cites = [] if bad or random.random() < 0.08 else [{"doc_id": f"POL-{random.randint(1, 40)}"}]
    inp, out = random.randint(300, 4000), random.randint(50, 600)
    cost = (inp + 3 * out) / 1_000_000 * MODELS[model]
    feedback = -1 if bad and random.random() < 0.6 else random.choice([1, None, None, -1 if random.random() < 0.05 else None])
    return (uuid.uuid4(), start + timedelta(minutes=i * 2), f"tenant-{random.randint(1, 12):02d}", model,
            version, inp, out, int(random.lognormvariate(7.2, 0.5)), status, round(cost, 6),
            json.dumps({"question": q, "route": route, "retries": random.choice([0, 0, 0, 1, 2])}),
            json.dumps({"answer": "...", "citations": cites}), feedback)

if __name__ == "__main__":
    start = datetime.now(timezone.utc) - timedelta(days=30)
    with psycopg.connect("postgresql://postgres:postgres@localhost/llmlogs") as conn:
        conn.execute(open("sql/00_schema.sql").read())
        with conn.cursor() as cur:
            cur.executemany("INSERT INTO llm_requests VALUES (%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s)",
                            [row(i, start) for i in range(21_600)])
```

<Hint>Task 4: one CTE computes rates per `(route, prompt_version)`; a second pivots with `max(rate) FILTER (WHERE prompt_version = 'v8')` and the same for `v7`. The seeded bug lives in the `coverage` route, so that is the row you should see flagged.</Hint>

<Hint>Task 5: compute `qhash` on the normalized question, use `DISTINCT ON (qhash)` ordered so failures win, then `row_number() OVER (PARTITION BY route, bucket ORDER BY random())`.
