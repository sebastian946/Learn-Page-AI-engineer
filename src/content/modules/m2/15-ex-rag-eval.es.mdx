## Objetivo

Convierte "se ve bien" en números. Vas a construir un golden dataset de 30 preguntas sobre el corpus hipotecario, ejecutar tu pipeline de `05-reranking` sobre él y puntuarlo con Ragas (faithfulness, answer relevance, context precision, context recall) más recall@5 determinista. Luego compararás dos configuraciones del pipeline y escribirás un reporte breve de evaluación.

Esta carpeta se convierte en la semilla de la suite de evals del proyecto final y del Módulo 3. Constrúyela como si otras personas fueran a ejecutarla: un solo comando, reproducible y versionada.

Carpeta: `rag-lab/06-evals/`.

**Time box:** 90 minutos. Más o menos 35 minutos para el dataset, 30 para el runner y 25 para el análisis y el reporte. No te saltes el análisis; es la parte por la que preguntan en las entrevistas.

## Requisitos del dataset

Escribe `data/golden.jsonl` con 30 ítems. Cada ítem:

```json
{"id": "gift-003", "question": "Are gift funds allowed for a down payment on an investment property?",
 "reference": "No. Gift funds are allowed only for primary residences and second homes.",
 "relevant_chunk_ids": ["uw-guide-5.1-9c2e"], "tags": ["gift-funds", "investment"],
 "difficulty": "lookup", "answerable": true}
```

Mezcla:

- Al menos 6 temas (DTI, LTV, fondos de regalo, reservas, eventos de crédito, tipos de propiedad, rate locks, costos de cierre).
- Al menos 18 `lookup`, 6 `multi_hop` (la respuesta necesita dos chunks) y 3 `numeric` (un cálculo o umbral).
- Al menos 4 ítems con `answerable: false`, cuya referencia sea "The policies do not cover this."
- `relevant_chunk_ids` debe apuntar a IDs de chunks reales de tu tabla pgvector. Escribe un pequeño script que lo verifique.

<AcceptanceCriteria>

- [ ] `data/golden.jsonl` tiene 30 ítems que cumplen el esquema, validados por un modelo Pydantic en `golden.py`.
- [ ] `scripts/check_golden.py` falla si algún `relevant_chunk_id` no existe en la base de datos.
- [ ] `run_eval.py --config baseline|rerank` ejecuta el pipeline sobre cada ítem y guarda los resultados crudos (respuesta, IDs y textos de chunks recuperados, latencia) en `runs/<timestamp>-<config>.jsonl`.
- [ ] Ragas puntúa faithfulness, response relevancy, context precision y context recall con un modelo juez fijado; recall@5 y MRR@10 deterministas se calculan a partir de los IDs de chunks.

- [ ] El reporte `reports/<date>.md` incluye una tabla agregada para ambas configuraciones, los 5 peores ítems con un diagnóstico de una línea cada uno (retrieval vs generación) y una recomendación.
- [ ] Las versiones de las librerías y el id del modelo juez quedan registrados en el encabezado del reporte.
- [ ] Volver a ejecutar la eval no vuelve a llamar al pipeline cuando `--from-run` apunta a un archivo de ejecución existente (separando generación de puntuación).

</AcceptanceCriteria>

```python
# 06-evals/golden.py
from __future__ import annotations

import json
from pathlib import Path
from typing import Literal

from pydantic import BaseModel, Field


class GoldenItem(BaseModel):
    id: str
    question: str
    reference: str
    relevant_chunk_ids: list[str] = Field(default_factory=list)
    tags: list[str]
    difficulty: Literal["lookup", "multi_hop", "numeric"]
    answerable: bool = True


def load_golden(path: Path = Path("data/golden.jsonl")) -> list[GoldenItem]:
    items = [GoldenItem.model_validate_json(line) for line in path.read_text("utf-8").splitlines() if line.strip()]
    ids = [i.id for i in items]
    assert len(ids) == len(set(ids)), "duplicate ids in golden set"
    return items


class RunRecord(BaseModel):
    item_id: str
    answer: str
    answer_found: bool
    retrieved_ids: list[str]
    retrieved_texts: list[str]
    latency_ms: float


def save_run(records: list[RunRecord], path: Path) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text("\n".join(r.model_dump_json() for r in records), "utf-8")
```

Abre el PDF, encuentra el párrafo, escribe la referencia con tus palabras y anota el ID del chunk.</Hint>

  <Hint>Ragas llama al juez muchas veces por muestra (extracción de afirmaciones, verificación). Si chocas con rate limits, usa un `RunConfig(max_workers=4, timeout=120)` y pásalo a `evaluate`. Pon la temperatura del juez en 0.</Hint>
  <Hint>Para el análisis de los 5 peores, ordena el dataframe por muestra según faithfulness y según context recall.
