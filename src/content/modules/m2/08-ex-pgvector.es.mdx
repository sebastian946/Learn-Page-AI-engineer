## Objetivo

Lleva tu retrieval de arreglos numpy en memoria a PostgreSQL con pgvector, como lo correrías en producción. Escribirás el schema, un indexador idempotente que solo vuelve a generar embeddings de los documentos que cambiaron, una función de consulta con filtros de metadata y un pequeño benchmark que compara el recall del ANN contra la búsqueda exacta y mide la latencia.

Carpeta: `rag-lab/03-pgvector/`. Entradas: `01-ingestion/out/documents.jsonl`, la estrategia de chunking que elegiste en `02-chunking/` y su golden set.

Al final de este ejercicio tendrás la capa de almacenamiento que el proyecto final (`mortgage-knowledge-assistant`) reutilizará casi sin cambios.

```python
# 03-pgvector/pgrag/db.py
import os
from datetime import date

import numpy as np
from pgvector.psycopg import register_vector_async
from psycopg import AsyncConnection
from psycopg.rows import dict_row

DSN = os.getenv("DATABASE_URL", "postgresql://rag:rag@localhost:5432/rag")
EMBED_MODEL = os.environ["EMBEDDING_MODEL"]


async def connect() -> AsyncConnection:
    conn = await AsyncConnection.connect(DSN, row_factory=dict_row, autocommit=False)
    await register_vector_async(conn)
    return conn


async def search(conn: AsyncConnection, qvec: np.ndarray, k: int = 5, *,
                 doc_type: str | None = None, jurisdictions: list[str] | None = None,
                 current_only: bool = True, effective_on: date | None = None,
                 ef_search: int = 40) -> list[dict]:
    await conn.execute(f"SET LOCAL hnsw.ef_search = {int(ef_search)}")
    await conn.execute("SET LOCAL hnsw.iterative_scan = relaxed_order")
    where, params = ["c.embedding_model = %(model)s"], {"model": EMBED_MODEL, "q": qvec, "k": k}
    if doc_type:
        where.append("d.doc_type = %(doc_type)s"); params["doc_type"] = doc_type
    if jurisdictions:
        where.append("d.jurisdiction = ANY(%(jur)s)"); params["jur"] = jurisdictions
    if current_only:
        where.append("d.is_current")
    if effective_on:
        where.append("d.effective_date <= %(eff)s"); params["eff"] = effective_on
    sql = f"""
        SELECT c.chunk_id, c.doc_id, c.section, c.page, c.content, d.title,
               1 - (c.embedding <=> %(q)s) AS similarity
        FROM chunks c JOIN documents d USING (doc_id)
        WHERE {' AND '.join(where)}
        ORDER BY c.embedding <=> %(q)s
        LIMIT %(k)s"""
    cur = await conn.execute(sql, params)
    return await cur.fetchall()
```

<Hints>
  <Hint>Solo se unen fragmentos SQL fijos en la cláusula `WHERE`; todo valor proporcionado por el usuario pasa por un parámetro `%(name)s`. El valor de `ef_search` se convierte con `int()` antes de formatearlo porque `SET` no acepta parámetros enlazados.</Hint>
  <Hint>Para la idempotencia, compara el `content_hash` antes de generar embeddings, no después. Envuelve "upsert del documento, borrar sus chunks, insertar los chunks nuevos" en `async with conn.transaction():` para que una caída nunca deje un documento indexado a medias.</Hint>
  <Hint>Para el recall del ANN, calcula la verdad de referencia con una búsqueda exacta: corre la misma consulta con `SET LOCAL enable_indexscan = off` (o calcula el coseno en numpy sobre todos los vectores de la tabla) y mide la intersección de los IDs del top-10 con el resultado de HNSW. En un corpus pequeño el recall será cercano a 1.0; es un hallazgo válido, anótalo.</Hint>

Luego pruébalo con `hnsw.iterative_scan` desactivado y observa la diferencia; menciónalo en el README.</Hint>
