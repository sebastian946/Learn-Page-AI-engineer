## Goal

Move your retrieval from in-memory numpy arrays to PostgreSQL with pgvector, the way you would run it in production. You will write the schema, an idempotent indexer that only re-embeds changed documents, a query function with metadata filters, and a small benchmark that checks ANN recall against exact search and measures latency.

Folder: `rag-lab/03-pgvector/`. Inputs: `01-ingestion/out/documents.jsonl`, the chunking strategy you chose in `02-chunking/`, and its golden set.

At the end of this exercise you have the storage layer the capstone (`mortgage-knowledge-assistant`) will reuse almost unchanged.

## Acceptance criteria

<AcceptanceCriteria>

- [ ] `docker compose up -d` at the root of `rag-lab` starts Postgres from the `pgvector/pgvector` image with a healthcheck and a named volume.
- [ ] `migrations/001_init.sql` creates the `vector` extension, a `documents` table (typed metadata columns: `doc_type`, `jurisdiction`, `effective_date`, `is_current`, `content_hash`) and a `chunks` table with `embedding_model` and a `vector(N)` column, plus an HNSW index using the operator class that matches your distance.
- [ ] `python -m pgrag index` loads documents, chunks them with your chosen strategy, embeds in batches, and upserts in a transaction per document. Re-running with no changes performs zero embedding calls and zero writes; changing one document re-embeds only that document's chunks.
- [ ] `search(query, k, filters)` supports filters on `doc_type`, `jurisdiction` (list), `is_current` and an `effective_on` date, using SQL parameters (no string formatting of user input).
- [ ] The query asserts that `embedding_model` in the table matches the configured model and fails loudly if not.
- [ ] `EXPLAIN ANALYZE` output in the README shows the HNSW index being used for an unfiltered query.
- [ ] A pytest integration test (running against the compose database) proves a selective filter still returns `k` results when at least `k` matching chunks exist.
- [ ] `python -m pgrag bench` reports, for the golden set: hit@5 and MRR@10, ANN recall@10 versus exact search, and p50/p95 query latency (excluding the query embedding call) at `hnsw.ef_search` 40 and 100.

</AcceptanceCriteria>

```python
# 03-pgvector/pgrag/db.py
import os
from datetime import date

import numpy as np
from pgvector.psycopg import register_vector_async
from psycopg import AsyncConnection
from psycopg.rows import dict_row

DSN = os.getenv("DATABASE_URL", "postgresql://rag:rag@localhost:5432/rag")
EMBED_MODEL = os.environ["EMBEDDING_MODEL"]


async def connect() -> AsyncConnection:
    conn = await AsyncConnection.connect(DSN, row_factory=dict_row, autocommit=False)
    await register_vector_async(conn)
    return conn


async def search(conn: AsyncConnection, qvec: np.ndarray, k: int = 5, *,
                 doc_type: str | None = None, jurisdictions: list[str] | None = None,
                 current_only: bool = True, effective_on: date | None = None,
                 ef_search: int = 40) -> list[dict]:
    await conn.execute(f"SET LOCAL hnsw.ef_search = {int(ef_search)}")
    await conn.execute("SET LOCAL hnsw.iterative_scan = relaxed_order")
    where, params = ["c.embedding_model = %(model)s"], {"model": EMBED_MODEL, "q": qvec, "k": k}
    if doc_type:
        where.append("d.doc_type = %(doc_type)s"); params["doc_type"] = doc_type
    if jurisdictions:
        where.append("d.jurisdiction = ANY(%(jur)s)"); params["jur"] = jurisdictions
    if current_only:
        where.append("d.is_current")
    if effective_on:
        where.append("d.effective_date <= %(eff)s"); params["eff"] = effective_on
    sql = f"""
        SELECT c.chunk_id, c.doc_id, c.section, c.page, c.content, d.title,
               1 - (c.embedding <=> %(q)s) AS similarity
        FROM chunks c JOIN documents d USING (doc_id)
        WHERE {' AND '.join(where)}
        ORDER BY c.embedding <=> %(q)s
        LIMIT %(k)s"""
    cur = await conn.execute(sql, params)
    return await cur.fetchall()
```

  <Hint>Only fixed SQL fragments are joined into the `WHERE` clause; every user-provided value goes through a `%(name)s` parameter. The `ef_search` value is cast with `int()` before formatting because `SET` does not accept bind parameters.</Hint>
  <Hint>For idempotency, compare `content_hash` before embedding, not after. Wrap "upsert document, delete its chunks, insert new chunks" in `async with conn.transaction():` so a crash never leaves a document half-indexed.</Hint>
