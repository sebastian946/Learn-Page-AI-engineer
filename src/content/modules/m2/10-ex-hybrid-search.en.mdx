## Goal

Add a keyword leg to your pgvector retriever, fuse the two legs with reciprocal rank fusion, enforce metadata filters on both legs, and prove with numbers that hybrid beats vector-only on your mortgage corpus, especially on questions with exact identifiers.

Folder: `rag-lab/04-hybrid/`. It builds on the database and indexer from `03-pgvector/` (same compose stack) and the golden set from `02-chunking/`.

### Extend the golden set first

Your current golden set probably under-represents the cases hybrid is meant to fix. Before writing code, add at least 12 questions in three categories and tag each with `category`:

- `exact_term` (at least 5): form numbers, section references, product codes. "What does Form 4506-C authorize?", "Section 50(a)(6) cash-out limits".
- `filtered` (at least 4): questions whose correct answer depends on jurisdiction or date, with `filters` recorded in the golden row, e.g. `{"jurisdiction": "US-TX"}` or an `as_of` date that selects the older FHA version.
- `paraphrase` (at least 3): no shared keywords with the source. "Highest debt ratio we'll take on a conforming loan?"

Per-category metrics will tell a much clearer story than one global number.

# 04-hybrid/hybrid/retrieve.py
from dataclasses import dataclass, field
from datetime import date

import numpy as np
from psycopg import AsyncConnection

from .fusion import rrf


@dataclass
class Filters:
    jurisdictions: list[str] = field(default_factory=lambda: ["US"])
    doc_type: str | None = None
    as_of: date | None = None
    current_only: bool = True


def filter_sql(f: Filters) -> tuple[str, dict]:
    where = ["d.jurisdiction = ANY(%(jur)s)"]
    params: dict = {"jur": sorted(set(f.jurisdictions) | {"US"})}
    if f.doc_type:
        where.append("d.doc_type = %(doc_type)s"); params["doc_type"] = f.doc_type
    if f.as_of:
        # TODO: select the version effective on as_of (latest effective_date <= as_of
        #       per document family). current_only must be ignored in this case.
        raise NotImplementedError
    elif f.current_only:
        where.append("d.is_current")
    return " AND ".join(where), params


async def vector_search(conn: AsyncConnection, qvec: np.ndarray, f: Filters, n: int = 40) -> list[str]:
    where, params = filter_sql(f)
    cur = await conn.execute(f"""
        SELECT c.chunk_id FROM chunks c JOIN documents d USING (doc_id)
        WHERE {where}
        ORDER BY c.embedding <=> %(q)s LIMIT %(n)s""", {**params, "q": qvec, "n": n})
    return [r["chunk_id"] for r in await cur.fetchall()]

async def hybrid_search(conn, qvec, text, f: Filters, k: int = 8,
                        rrf_k: int = 60, w_vec: float = 0.5) -> list[str]:
    vec_ids = await vector_search(conn, qvec, f)
    kw_ids = await keyword_search(conn, text, f)
    fused = rrf([vec_ids, kw_ids], k=rrf_k, weights=[w_vec, 1 - w_vec], top_n=k)

from hybrid.fusion import rrf

def test_rrf_prefers_items_in_both_lists():
    fused = dict(rrf([["a", "b", "c"], ["c", "d", "a"]], k=60))
    # a: 1/61 + 1/63, c: 1/63 + 1/61 -> tie; both beat b and d
    assert abs(fused["a"] - fused["c"]) < 1e-12
    assert fused["a"] > fused["b"] and fused["a"] > fused["d"]

## Hints

<Hints>
  <Hint>Run the two legs concurrently with `asyncio.gather`, each on its own connection from a pool (`psycopg_pool.AsyncConnectionPool`). A single connection cannot run two queries at the same time.</Hint>
  <Hint>Check identifier tokenization in `psql` first: `SELECT to_tsvector('english', 'Form 4506-C and Section 50(a)(6)');`. If an identifier is split into pieces that also match unrelated chunks, add a second generated column using the `simple` configuration over a normalized copy of the text (strip hyphens and parentheses), and OR both tsqueries in the keyword leg.</Hint>
  <Hint>For `as_of`, you need a document family key that is stable across versions (for example the slug from the file path in `01-ingestion`). Use `DISTINCT ON (family) ... ORDER BY family, effective_date DESC` restricted to `effective_date <= as_of` in a CTE, and join chunks to that set.</Hint>
  <Hint>Expect the per-category table to show keyword winning on `exact_term`, vector winning on `paraphrase`, and hybrid close to the best of both on each. If hybrid loses on `paraphrase`, your keyword weight is too high or each leg returns too few candidates; if it loses on `exact_term`, check tokenization before touching weights.</Hint>
