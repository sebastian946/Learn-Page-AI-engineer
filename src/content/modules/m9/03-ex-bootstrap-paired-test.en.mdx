## Goal

Your team has two prompts for the support ticket router from Module 1: `v1` (in production) and `v2` (a rewrite with clearer category definitions). Someone ran both once and posted "v2 is 3 points better!" in Slack. Your job is to produce an answer that would survive a skeptical staff engineer:

1. Run both prompts on the **same** labeled tickets, 3 times each, with caching.
2. Measure the A/A noise floor (v1 vs v1).
3. Report accuracy and macro-F1 for each prompt with 95% bootstrap confidence intervals.
4. Report the **paired** difference with a CI, an exact McNemar test and a paired permutation test.
5. Estimate how many items you would need to detect a 3-point difference with 80% power.
6. Write a one-page `REPORT.md` that ends with a clear recommendation.

This is the first folder of a new repo, `llm-eval-lab`, which collects all Module 9 exercises.

## Context

Use at least 200 labeled tickets. Reuse the dataset from `support-ticket-router` if you have it. Otherwise, generate a seed set with an LLM, then **relabel every item yourself** so the gold labels are human labels. Keep at least 5 categories, and make sure one category is rare (5–8% of items), for example `legal_threat`. Rare classes are where macro-F1 and accuracy disagree.

Row format for `data/tickets.jsonl`:

```json
{"id": "t-0042", "text": "I was charged twice for order 88123 and want my money back today.", "label": "billing_refund"}
```

Prediction cache format for `runs/<prompt>-run<k>.jsonl`:

```json
{"id": "t-0042", "pred": "billing_refund", "latency_ms": 812, "input_tokens": 412, "output_tokens": 9}
```

- [ ] Exact McNemar (via `scipy.stats.binomtest`) and a paired permutation test are reported with the discordant counts
- [ ] An A/A comparison (v1 run 1 vs v1 run 2) is reported as the noise floor
- [ ] A sample-size estimate for detecting a 3-point accuracy difference at alpha 0.05 and 80% power uses the observed discordant rate
- [ ] `REPORT.md` leads with effect size and CI, then p-values, then a recommendation (ship, do not ship, or collect more data) with the reasoning
- [ ] All random operations use a fixed seed; rerunning `analyze.py` gives identical numbers

<Hints>
  <Hint>Separate generation from analysis. `run_prompts.py` is the only file that calls the API. `analyze.py` reads only cached files, so you can iterate on statistics for free. Use the prompt file's SHA-256 in the cache key so editing `v2.md` invalidates its runs automatically.</Hint>
  <Hint>Macro-F1 is not an average of per-item scores, so you cannot bootstrap a vector of per-item numbers. Resample indices and recompute the whole metric on each resample, for both prompts on the same indices. That is what makes it paired.</Hint>
  <Hint>For McNemar, build boolean vectors `correct_a = pred_a == gold` and `correct_b = pred_b == gold`. `a_only = (correct_a & ~correct_b).sum()`. The discordant rate for the sample-size formula is `(a_only + b_only) / n`. If your A/A test already shows 5% discordance, your items are noisy and majority voting across runs matters.</Hint>
  <Hint>A good report structure: one table with accuracy and macro-F1 per prompt and CIs; one table with paired differences, CIs and p-values; one line with the A/A floor; one line with the required n; then the recommendation. If the CI on the difference includes 0, the honest answer is "no evidence that v2 is better at n = 200; we need about N items", not "v2 is slightly better".</Hint>
