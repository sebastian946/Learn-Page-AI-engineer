## Goal

Rewrite your resume bullets, LinkedIn headline and LinkedIn About section using the module-to-keyword mapping from the previous lesson. Then measure the result against three real job postings, the way you would measure test coverage.

You will produce a versioned `career/` folder in your portfolio hub repo (`ai-engineer-portfolio`, from Module 0). Resume content lives as markdown and YAML so you can diff versions, tailor per posting, and generate a PDF.

Context: the previous lesson gave you a formula (action + what + technology + measured result) and a coverage checker. Here you apply both to your own history. Expect the first draft to be weak. The second pass, where every number is checked against an artifact, is where the value is.

Steps:

1. **Collect evidence (15 min).** For each capstone, open its README results table, eval report and cost analysis. Write down every measured number with a link to where it comes from. This is your evidence file.
2. **Pick three target postings (10 min).** Real, current postings for roles you would accept. Save the text as files (postings change or disappear).
3. **Draft bullets (20 min).** 2 to 3 bullets per capstone, 3 to 5 per SDET role. Use the formula. Every number must appear in your evidence file.
4. **Run coverage (10 min).** Use the checker against each posting. Fix honest gaps (you used the skill but did not mention it). Note dishonest gaps (you lack the skill) as learning items, not resume lines.
5. **LinkedIn (15 min).** Headline, About, Featured section plan, top skills order.
6. **Peer read (5 min).** Read the result aloud. Anything that sounds like a duty instead of an outcome gets rewritten.

<AcceptanceCriteria>

- [ ] `career/evidence.md` lists every number used in the resume, each with a link to the repo artifact that proves it.
- [ ] `career/resume.yaml` has a headline, 3-line summary, grouped skills, projects (final capstone first) and rewritten experience.
- [ ] Every bullet follows action + what + technology + measured result, and is under 2 lines.
- [ ] No tool appears in the resume that you have not used in a project or job.
- [ ] `career/postings/` contains 3 saved postings and `career/coverage.md` shows coverage per posting before and after the rewrite, with remaining gaps listed.
- [ ] `career/linkedin.md` has a headline under 220 characters, an About of 3 paragraphs ending with a call to action, a Featured plan and the ordered top 10 skills.
- [ ] The coverage script runs with `python career/check.py` and prints a table.

</AcceptanceCriteria>

```python
# career/check.py - coverage of each saved posting vs the resume
from pathlib import Path
import yaml
from keywords import found  # the KEYWORDS + found() function from lesson 07

def resume_text(path: Path) -> str:
    data = yaml.safe_load(path.read_text(encoding="utf-8"))
    parts = [data["headline"], data["summary"]]
    parts += [s for group in data["skills"].values() for s in group]
    for section in ("projects", "experience"):
        parts += [b for item in data[section] for b in item["bullets"]]
    return "\n".join(parts)

def main() -> None:
    resume = found(resume_text(Path("career/resume.yaml")))
    print(f"{'posting':40} {'coverage':>8}  missing")
    for p in sorted(Path("career/postings").glob("*.txt")):
        wanted = found(p.read_text(encoding="utf-8"))
        pct = round(100 * len(wanted & resume) / max(len(wanted), 1))
        print(f"{p.stem:40} {pct:>7}%  {', '.join(sorted(wanted - resume))}")

if __name__ == "__main__":
    main()
```

<Hints>
  <Hint>Start from the evidence, not from the bullet. Open each capstone's eval report and write the numbers first. A bullet built around a real number writes itself; a bullet built around an adjective never gets a number.</Hint>
  <Hint>For SDET bullets, ask "what changed because of my work?" Fewer escaped defects, shorter CI time, a framework other teams adopted, a release unblocked. Then use AI-adjacent vocabulary from the translation table: "designed quality gates", "built evaluation infrastructure", "reduced non-determinism in test signals".</Hint>
  <Hint>Keep the LinkedIn headline in three parts separated by vertical bars: role and core skills, proof (the capstone in a few words), differentiator (ex-SDET who makes AI reliable). Check its length with `len(headline)`; LinkedIn cuts at 220 characters.</Hint>
  <Hint>If coverage stays low for a posting after honest fixes, that posting is either a stretch role or needs a skill you do not have. Record the gap in `coverage.md` with a plan (for example "Pinecone: port rag-lab retriever to Pinecone, 2 hours") instead of adding the keyword.</Hint>
