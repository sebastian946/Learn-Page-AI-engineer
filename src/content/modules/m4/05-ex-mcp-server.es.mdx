## Objetivo

Construye un servidor MCP con forma de producción para una empresa de logística ficticia, **Northstar Freight**. Expone datos de pedidos e inventario a cualquier cliente MCP: Claude Desktop, el MCP Inspector o el agente LangGraph que construirás en el ejercicio 08.

Vas a entregar:

- **3 tools**: `get_order` (lectura), `check_stock` (lectura), `reschedule_delivery` (escritura, idempotente).
- **1 resource**: `inventory://warehouses`, la lista de bodegas con sus horarios de corte.
- Un **contrato de error estructurado** en cada tool (lección 03).
- Tests con **pytest** que pasan por una sesión real de cliente MCP, no solo llamadas directas a funciones.
- Notas y una captura de pantalla de una sesión manual en el **MCP Inspector**.

Esto vive en el repo `mcp-servers-lab`, carpeta `orders_server/`. Tiempo límite: 90 minutos.

Los datos pueden estar en memoria o en SQLite. Mantén el almacenamiento detrás de una clase pequeña para que los tests puedan reiniciarlo entre ejecuciones, igual que aíslas fixtures en Playwright.

<AcceptanceCriteria>

- [ ] `uv run python -m orders_server` (o `python -m orders_server`) inicia el servidor sobre stdio; `--http` lo inicia con `transport="streamable-http"` en `127.0.0.1:8000`.
- [ ] `get_order(order_id)` valida el formato del id `ORD-` seguido de 6 dígitos y devuelve `order_id`, `status`, `carrier`, `promised_date`, `warehouse_id`.
- [ ] `check_stock(sku, warehouse_id)` devuelve las cantidades `available` y `reserved`; `warehouse_id` es opcional y, si se omite, devuelve totales por bodega.
- [ ] `reschedule_delivery(order_id, new_date, idempotency_key)` rechaza pedidos entregados o cancelados, rechaza fines de semana y fechas a más de 14 días, y devuelve el resultado guardado ante un `idempotency_key` repetido con `"replayed": true`.
- [ ] Cada error de negocio usa la forma `{"error": {"code", "message", "retryable", "hint"}}` con al menos estos códigos: `INVALID_ORDER_ID`, `ORDER_NOT_FOUND`, `ALREADY_DELIVERED`, `INVALID_DATE`, `UNKNOWN_SKU`.
- [ ] El resource `inventory://warehouses` devuelve JSON con al menos 3 bodegas (`id`, `city`, `cutoff_local`).
- [ ] Los docstrings de los tools dicen qué hace el tool, cuándo usarlo, qué devuelve y si cambia estado.
- [ ] Nada se imprime a stdout; los logs van a stderr o a `ctx.info`.
- [ ] `pytest` pasa con al menos 8 tests, incluyendo uno que lista los tools a través de una sesión de cliente y uno que demuestra el replay idempotente.
- [ ] El README incluye una captura del Inspector y el comando exacto para reproducirla.

</AcceptanceCriteria>

# tests/test_server.py
import pytest
from mcp.shared.memory import create_connected_server_and_client_session
from orders_server import server


@pytest.fixture(autouse=True)
def fresh_store(monkeypatch):
    monkeypatch.setattr(server, "store", server.Store.seeded())


@pytest.mark.anyio
async def test_lists_three_tools():
    async with create_connected_server_and_client_session(server.mcp._mcp_server) as client:
        tools = await client.list_tools()
        assert {t.name for t in tools.tools} == {"get_order", "check_stock", "reschedule_delivery"}


@pytest.mark.anyio
async def test_unknown_order_returns_contract():
    result = await server.get_order("ORD-000000")
    assert result["error"]["code"] == "ORDER_NOT_FOUND"
    assert result["error"]["retryable"] is False

<Hints>

<Hint>Empieza con la clase `Store`: diccionarios para pedidos, stock y un mapa `idempotency` de llave a respuesta. Dale un classmethod `seeded()` con 5 pedidos en distintos estados (pending, in_transit, delayed, delivered, cancelled). Los tests se vuelven triviales cuando los datos son predecibles.</Hint>

<Hint>En `reschedule_delivery`, revisa el mapa de idempotencia **antes** de cualquier validación. Un replay de una llamada exitosa debe tener éxito aunque el estado del pedido haya cambiado desde entonces (por ejemplo, ahora está "rescheduled"). Guarda solo respuestas exitosas, no errores.</Hint>

<Hint>Verificación de fin de semana y ventana: `new_date.weekday() >= 5` es fin de semana; compara contra `date.today() + timedelta(days=14)`. Inyecta "hoy" a través del store (`store.today`) para que los tests no se rompan los viernes. Es la versión del mundo de agentes de congelar el tiempo en un test E2E flaky.</Hint>

<Hint>`create_connected_server_and_client_session` recibe el servidor de bajo nivel, que FastMCP expone como `mcp._mcp_server`. `call_tool` devuelve un `CallToolResult`; el JSON está en `result.content[0].text` (y en `result.structuredContent` en versiones recientes del SDK). Agrega `anyio` a las dependencias de desarrollo y usa `@pytest.mark.anyio`. Para probar el resource, llama `client.read_resource("inventory://warehouses")`.</Hint>
