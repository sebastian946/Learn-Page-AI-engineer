## Goal

Build a production-shaped MCP server for a fictional logistics company, **Northstar Freight**. It exposes order and inventory data to any MCP client: Claude Desktop, the MCP Inspector, or the LangGraph agent you will build in exercise 08.

You will ship:

- **3 tools**: `get_order` (read), `check_stock` (read), `reschedule_delivery` (write, idempotent).
- **1 resource**: `inventory://warehouses`, the list of warehouses with cut-off times.
- A **structured error contract** on every tool (lesson 03).
- **pytest** tests that go through a real MCP client session, not just direct function calls.
- Notes and a screenshot from a manual session in the **MCP Inspector**.

This lives in the `mcp-servers-lab` repo, folder `orders_server/`. Time box: 90 minutes.

Data can be in memory or SQLite. Keep the store behind a small class so tests can reset it between runs, the same way you isolate fixtures in Playwright.

<AcceptanceCriteria>

- [ ] `uv run python -m orders_server` (or `python -m orders_server`) starts the server over stdio; `--http` starts it with `transport="streamable-http"` on `127.0.0.1:8000`.
- [ ] `get_order(order_id)` validates the id format `ORD-` followed by 6 digits and returns `order_id`, `status`, `carrier`, `promised_date`, `warehouse_id`.
- [ ] `check_stock(sku, warehouse_id)` returns `available` and `reserved` quantities; `warehouse_id` is optional and, when omitted, returns totals per warehouse.
- [ ] `reschedule_delivery(order_id, new_date, idempotency_key)` rejects delivered or cancelled orders, rejects weekends and dates more than 14 days ahead, and returns the stored result on a repeated `idempotency_key` with `"replayed": true`.
- [ ] Every business error uses the shape `{"error": {"code", "message", "retryable", "hint"}}` with at least these codes: `INVALID_ORDER_ID`, `ORDER_NOT_FOUND`, `ALREADY_DELIVERED`, `INVALID_DATE`, `UNKNOWN_SKU`.
- [ ] Resource `inventory://warehouses` returns JSON with at least 3 warehouses (`id`, `city`, `cutoff_local`).
- [ ] Tool docstrings state what the tool does, when to use it, what it returns and whether it changes state.
- [ ] Nothing is printed to stdout; logs go to stderr or `ctx.info`.
- [ ] `pytest` passes with at least 8 tests, including one that lists tools through a client session and one that proves idempotent replay.
- [ ] README includes an Inspector screenshot and the exact command to reproduce it.

</AcceptanceCriteria>

# tests/test_server.py
import pytest
from mcp.shared.memory import create_connected_server_and_client_session
from orders_server import server


@pytest.fixture(autouse=True)
def fresh_store(monkeypatch):
    monkeypatch.setattr(server, "store", server.Store.seeded())


@pytest.mark.anyio
async def test_lists_three_tools():
    async with create_connected_server_and_client_session(server.mcp._mcp_server) as client:
        tools = await client.list_tools()
        assert {t.name for t in tools.tools} == {"get_order", "check_stock", "reschedule_delivery"}


@pytest.mark.anyio
async def test_unknown_order_returns_contract():
    result = await server.get_order("ORD-000000")
    assert result["error"]["code"] == "ORDER_NOT_FOUND"
    assert result["error"]["retryable"] is False

<Hints>

<Hint>Start with the `Store` class: dictionaries for orders, stock and an `idempotency` map from key to response. Give it a `seeded()` classmethod with 5 orders in different statuses (pending, in_transit, delayed, delivered, cancelled). Tests become trivial once the data is predictable.</Hint>

<Hint>In `reschedule_delivery`, check the idempotency map **before** any validation. A replay of a successful call must succeed even if the order status changed since (for example, it is now "rescheduled"). Only store successful responses, not errors.</Hint>

<Hint>Weekend and window checks: `new_date.weekday() >= 5` is a weekend; compare against `date.today() + timedelta(days=14)`. Inject "today" through the store (`store.today`) so tests do not break on Fridays. That is the agent-world version of freezing time in a flaky E2E test.</Hint>

<Hint>`create_connected_server_and_client_session` takes the low-level server, which FastMCP exposes as `mcp._mcp_server`. `call_tool` returns a `CallToolResult`; the JSON is in `result.content[0].text` (and in `result.structuredContent` on recent SDK versions). Add `anyio` to dev dependencies and use `@pytest.mark.anyio`. To test the resource, call `client.read_resource("inventory://warehouses")`.</Hint>
