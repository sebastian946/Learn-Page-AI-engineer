## Goal

In exercise 08 you built `langgraph-hitl-agent`: a LangGraph agent with an approval gate before risky tools. Right now nothing stops it from looping forever or spending without limit. In this exercise you add three guards and prove each one with a deterministic test:

1. **Max steps** — the agent stops after `MAX_STEPS` model calls.
2. **Repeated-action detection** — the agent stops when the same tool call (name plus arguments) appears `REPEAT_THRESHOLD` times.
3. **Per-run cost budget** — the agent stops before a model call that would push the run over `MAX_COST_USD`.

Every stop must be graceful: a clear final message, a `stop_reason` in state, and a ticket for a human. No exceptions reaching the caller.

Time box: 60 minutes. You will not call a real model. Tests use a fake chat model that loops on purpose, the same way you would stub a flaky dependency in an integration test.

## Context

Think of this as adding timeouts and circuit breakers to a service you already own. The guards live in the graph, not in the prompt. A prompt that says "do not repeat yourself" is a suggestion. A router that checks a counter is a contract.

Pricing values come from `config/pricing.yaml`. Use example values and label them as examples. The tests should inject their own prices so they never depend on real pricing.

<AcceptanceCriteria>

- [ ] `AgentState` has `step_count: int`, `cost_usd: float` and `stop_reason: str | None`, with sensible defaults set at graph input.
- [ ] The agent node increments `step_count` and adds the cost of each response computed from `usage_metadata` and a prices dict.
- [ ] A guard router runs after the agent node and before tools. It routes to `stop` on max steps, repeated action or budget, to `tools` on tool calls, and to `END` otherwise.
- [ ] The budget check uses a pre-call estimate, so a call that would exceed the budget is never made.
- [ ] The `stop` node writes a user-facing `AIMessage`, sets `stop_reason` to one of `max_steps`, `repeated_action`, `budget`, and calls `create_ticket` with the thread id.
- [ ] `recursion_limit` is still set in the invoke config as a backstop, higher than `MAX_STEPS * 2 + 5`.
- [ ] Limits are read from env or config (`MAX_STEPS`, `REPEAT_THRESHOLD`, `MAX_COST_USD`) with defaults.
- [ ] Three pytest tests, one per guard, using a fake model. No network. Total test time under 2 seconds.
- [ ] One test proves a normal run (two tool calls then a final answer) is not affected by the guards.
- [ ] README has a "Guards" section with the limits, how they were chosen, and the `stop_reason` values.

</AcceptanceCriteria>

def call_signature(name: str, args: dict) -> str:
    canonical = json.dumps(args, sort_keys=True, separators=(",", ":"))

from langgraph.checkpoint.memory import MemorySaver
from hitl_agent.graph import build_graph
from tests.fakes import ScriptedModel  # from exercise 08
from langchain_core.messages import AIMessage

def looping_model(n: int = 50) -> ScriptedModel:
    msgs = [AIMessage(content="", tool_calls=[{
        "name": "get_order", "args": {"order_id": "ORD-1001"}, "id": f"call_{i}"}],
        usage_metadata={"input_tokens": 1200, "output_tokens": 40, "total_tokens": 1240})
        for i in range(n)]
    return ScriptedModel(msgs)

def test_repeated_action_stops_run(fake_backend):
    graph = build_graph(looping_model(), MemorySaver(), backend=fake_backend)
    out = graph.invoke({"messages": [("user", "Where is ORD-1001?")]},
                       config={"configurable": {"thread_id": "t-repeat"}, "recursion_limit": 40})
