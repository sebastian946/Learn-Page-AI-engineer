## Objetivo

Tu `mortgage-knowledge-assistant` del módulo 2 funciona, pero cuando una respuesta es incorrecta no puedes ver por qué. En este ejercicio le agregas tracing de nivel producción. Cada request debe producir un trace con un span por paso del pipeline, atributos de tokens y costo en el span del LLM, un trace id devuelto al cliente y un score de feedback vinculado al trace.

Vas a instrumentar con OpenTelemetry (neutral respecto al vendor) y ver los traces en Jaeger localmente. Opcionalmente, también exportas a Langfuse (nube o self-hosted) para obtener vistas y scores específicos de LLM. Si prefieres LangSmith, la misma estructura funciona con `@traceable` y `create_feedback`; documenta tu elección en el README.

Tiempo límite: 75 minutos.

**Dónde va el código:** la instrumentación vive en `mortgage-knowledge-assistant` bajo `app/observability/`. Las notas, screenshots y el análisis de traces van a `llm-eval-harness/tracing/`.

Recuerda el sistema bajo prueba: `async def answer(question: str) -> RagResult` con los campos `answer`, `citations`, `contexts`, `usage` (`input_tokens`, `output_tokens`) y `latency_ms`. Pasos: `rewrite_query`, luego `hybrid_retrieve`, luego `rerank`, luego `generate` con `claude-sonnet-5-5`.

## Criterios de aceptación

<AcceptanceCriteria>

- [ ] `docker compose up` levanta la app y Jaeger (OTLP en 4318, UI en 16686).
- [ ] Un `POST /ask` produce exactamente un trace con un span raíz del servidor y spans hijos `rewrite_query`, `retrieve hybrid`, `rerank` y `chat claude-sonnet-5-5`.
- [ ] El span del LLM lleva `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons` y un atributo propio `app.cost_usd`.
- [ ] El span de retrieval registra `rag.retrieval.top_k` y `rag.retrieval.doc_ids` (solo ids, sin texto completo de documentos).
- [ ] La respuesta incluye un header `X-Trace-Id` y un campo `trace_id`.
- [ ] `POST /feedback` con `trace_id` y `score` vincula el score al trace (un score de Langfuse, un feedback de LangSmith, o un evento en un span `feedback` con el mismo trace id en modo solo Jaeger).
- [ ] Los errores de la llamada al LLM se registran con `record_exception` y status ERROR.
- [ ] Los nombres de atributos viven en un módulo de constantes. El contenido de prompts y completions NO se captura a menos que `OTEL_CAPTURE_CONTENT=true`.
- [ ] Un test unitario usa `InMemorySpanExporter` para verificar los nombres de spans y los atributos de tokens.
- [ ] `tracing/README.md` en `llm-eval-harness` contiene un screenshot de un trace y un recorrido corto de "cómo depuré una mala respuesta".

</AcceptanceCriteria>

```python
# app/observability/cost.py
from pydantic import BaseModel

class Price(BaseModel):
    input_per_mtok: float
    output_per_mtok: float

# Example values only. Load real prices from config and check the provider's current pricing.
PRICES: dict[str, Price] = {
    "claude-sonnet-5-5": Price(input_per_mtok=3.0, output_per_mtok=15.0),
}

def cost_usd(model: str, input_tokens: int, output_tokens: int) -> float:
    p = PRICES.get(model)
    if p is None:
        return 0.0
    return (input_tokens * p.input_per_mtok + output_tokens * p.output_per_mtok) / 1_000_000
```

```python
import pytest
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor
from opentelemetry.sdk.trace.export.in_memory_span_exporter import InMemorySpanExporter

exporter = InMemorySpanExporter()
provider = TracerProvider()
provider.add_span_processor(SimpleSpanProcessor(exporter))  # fine in tests
```

## Pistas

<Hints>
  <Hint>Empieza por la configuración: crea el `TracerProvider` una sola vez al iniciar la app (lifespan de FastAPI), agrega un `BatchSpanProcessor` con el exporter OTLP HTTP y llama a `provider.shutdown()` al apagar. Luego agrega `FastAPIInstrumentor.instrument_app(app)` para que cada request tenga un span raíz gratis.</Hint>
  <Hint>Envuelve cada función del pipeline con `tracer.start_as_current_span(...)` en lugar de pasar spans de un lado a otro. Como usas `start_as_current_span`, los spans hijos se adjuntan automáticamente al request actual, incluso a través de `await`.</Hint>
  <Hint>Lee el trace id dentro del handler con `trace.get_current_span().get_span_context().trace_id` y formatéalo como 32 caracteres hexadecimales con `format(trace_id, "032x")`. Es el mismo id que muestra Jaeger y el que usa Langfuse para traces OTLP.</Hint>
  <Hint>Para el feedback en modo solo Jaeger, no puedes agregar nada a un trace terminado. Crea un span nuevo llamado `feedback` y guarda el trace id original como atributo (`app.feedback.trace_id`), más un span link si tienes el span context. Con Langfuse, llama a la API de scores del SDK con el trace id; es la opción más limpia y la que debes mencionar en entrevistas.</Hint>
</Hints>
