## Goal

Your Module 2 `mortgage-knowledge-assistant` works, but when an answer is wrong you can't see why. In this exercise you add production-grade tracing to it. Every request should produce one trace with a span per pipeline step, token and cost attributes on the LLM span, a trace id returned to the client, and a feedback score linked back to the trace.

You will instrument with OpenTelemetry (vendor-neutral) and view traces in Jaeger locally. Optionally, you also export to Langfuse (cloud or self-hosted) to get LLM-specific views and scores. If you prefer LangSmith, the same structure works with `@traceable` and `create_feedback`; document your choice in the README.

Time box: 75 minutes.

**Where the code goes:** instrumentation lives in `mortgage-knowledge-assistant` under `app/observability/`. Notes, screenshots and the trace-reading write-up go to `llm-eval-harness/tracing/`.

Recall the system under test: `async def answer(question: str) -> RagResult` with fields `answer`, `citations`, `contexts`, `usage` (`input_tokens`, `output_tokens`) and `latency_ms`. Steps: `rewrite_query`, then `hybrid_retrieve`, then `rerank`, then `generate` with `claude-sonnet-5-5`.

## Acceptance criteria

<AcceptanceCriteria>

- [ ] `docker compose up` starts the app and Jaeger (OTLP on 4318, UI on 16686).
- [ ] One `POST /ask` produces exactly one trace with a root server span and child spans `rewrite_query`, `retrieve hybrid`, `rerank` and `chat claude-sonnet-5-5`.
- [ ] The LLM span carries `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.finish_reasons` and a custom `app.cost_usd` attribute.
- [ ] The retrieval span records `rag.retrieval.top_k` and `rag.retrieval.doc_ids` (ids only, no full document text).
- [ ] The response includes an `X-Trace-Id` header and a `trace_id` field.
- [ ] `POST /feedback` with `trace_id` and `score` links the score to the trace (a Langfuse score, a LangSmith feedback, or a span event on a `feedback` span with the same trace id in Jaeger-only mode).
- [ ] Errors from the LLM call are recorded with `record_exception` and an ERROR status.
- [ ] Attribute names live in one constants module. Prompt and completion content is NOT captured unless `OTEL_CAPTURE_CONTENT=true`.
- [ ] A unit test uses `InMemorySpanExporter` to assert the span names and the token attributes.
- [ ] `tracing/README.md` in `llm-eval-harness` contains a screenshot of a trace and a short "how I debugged one bad answer" walkthrough.

</AcceptanceCriteria>

```python
# app/observability/cost.py
from pydantic import BaseModel

class Price(BaseModel):
    input_per_mtok: float
    output_per_mtok: float

# Example values only. Load real prices from config and check the provider's current pricing.
PRICES: dict[str, Price] = {
    "claude-sonnet-5-5": Price(input_per_mtok=3.0, output_per_mtok=15.0),
}

def cost_usd(model: str, input_tokens: int, output_tokens: int) -> float:
    p = PRICES.get(model)
    if p is None:
        return 0.0
    return (input_tokens * p.input_per_mtok + output_tokens * p.output_per_mtok) / 1_000_000
```

```python
# tests/test_tracing.py
import pytest
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor
from opentelemetry.sdk.trace.export.in_memory_span_exporter import InMemorySpanExporter

exporter = InMemorySpanExporter()
provider = TracerProvider()
provider.add_span_processor(SimpleSpanProcessor(exporter))  # fine in tests
trace.set_tracer_provider(provider)

@pytest.mark.asyncio
async def test_answer_emits_expected_spans(fake_llm, fake_retriever) -> None:
    from app.rag import answer
    await answer("What is the max DTI for an FHA loan?")
```

## Hints

<Hints>
  <Hint>Start with setup: create the `TracerProvider` once at app startup (FastAPI lifespan), add a `BatchSpanProcessor` with the OTLP HTTP exporter, and call `provider.shutdown()` on shutdown. Then add `FastAPIInstrumentor.instrument_app(app)` so every request gets a root span for free.</Hint>
  <Hint>Wrap each pipeline function with `tracer.start_as_current_span(...)` instead of passing spans around. Because you use `start_as_current_span`, child spans attach to the current request automatically, even across `await`.</Hint>
  <Hint>Read the trace id inside the request handler with `trace.get_current_span().get_span_context().trace_id` and format it as 32 hex chars with `format(trace_id, "032x")`. That is the same id Jaeger shows and the id Langfuse uses for OTLP traces.</Hint>
  <Hint>For feedback in Jaeger-only mode, you cannot append to a finished trace. Create a new span named `feedback` and set the original trace id as an attribute (`app.feedback.trace_id`) plus a span link if you have the span context. With Langfuse, call the SDK's score API with the trace id instead; that is the cleaner option and the one to mention in interviews.</Hint>
</Hints>
