## Goal

Milestone 2 of `llm-provider-client`. Use your client to turn messy customer **return-request emails** into validated Pydantic objects, with a bounded **repair loop**, field-level accuracy measurement and a repair-rate metric.

The scenario: an e-commerce returns team receives free-text emails ("hi, the boots A-20931 are too small and the jacket arrived torn, can I get store credit?"). They want each email turned into a structured return request that their warehouse system can consume. Wrong data creates real cost: a wrong SKU means the wrong refund.

Time box: 60 minutes.

## The target schema

```python
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, field_validator, model_validator

class ReturnItem(BaseModel):
    model_config = ConfigDict(extra="forbid")
    description: str = Field(description="Item as the customer describes it")
    quantity: int = Field(ge=1, le=20)
    reason: Literal["wrong_size", "damaged", "not_as_described", "changed_mind", "other"]

class ReturnRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    order_id: str | None = Field(description="Format A-12345, null if not mentioned")
    items: list[ReturnItem] = Field(min_length=1)
    preferred_resolution: Literal["refund", "store_credit", "exchange", "unspecified"]
    customer_sentiment: Literal["positive", "neutral", "negative"]
    needs_human: bool = Field(description="True if threats, legal language or safety issues")

    @field_validator("order_id")
    @classmethod
    def check_order_id(cls, v: str | None) -> str | None:
        if v is not None and (not v.startswith("A-") or not v[2:].isdigit() or len(v) != 7):
            raise ValueError("order_id must match A-12345")
        return v

    @model_validator(mode="after")
    def damaged_items_need_human_if_many(self) -> "ReturnRequest":
        damaged = sum(i.quantity for i in self.items if i.reason == "damaged")
        if damaged >= 3 and not self.needs_human:
            raise ValueError("3+ damaged units must set needs_human=true")
        return self
```

The `model_validator` encodes a business rule the schema alone cannot express. It is exactly the kind of rule a repair loop can fix.

- [ ] Validation uses `ReturnRequest.model_validate_json`; on `ValidationError` it sends the previous output and `exc.errors()` back to the model, at most 2 repairs.
- [ ] After the repair budget, it raises `ExtractionFailed` carrying the raw output and errors; it never returns an invalid object.
- [ ] Responses with `stop_reason` `max_tokens` or `refusal` are treated as failures, not repaired blindly.
- [ ] `evaluate.py` prints per-field accuracy (order_id, resolution, sentiment, needs_human, item count), overall exact-match rate, repair rate and total cost from the cost log.
- [ ] Unit tests with `FakeProvider` cover: valid first try, invalid JSON then valid, business-rule violation then valid, and repair budget exhausted.
- [ ] README section for milestone 2 reports your measured numbers and one example of a repair that worked.

## Starter code

<StarterCode>

```python
# milestones/m2_structured_extraction/extract.py
import json
from dataclasses import dataclass, field
from pydantic import ValidationError

from llm_client import LLMClient, LLMRequest
from llm_client.prompts import load_prompt
from llm_client.types import StopReason
from .schema import ReturnRequest

PROMPT = load_prompt("return-extraction", "1.0.0")

@dataclass
class ExtractionStats:
    calls: int = 0
    repairs: int = 0
    failures: int = 0
    errors_by_type: dict[str, int] = field(default_factory=dict)

class ExtractionFailed(Exception):
    def __init__(self, raw: str, errors: list[dict]) -> None:
        super().__init__(f"extraction failed: {errors[:2]}")
        self.raw, self.errors = raw, errors

async def extract_return(
    client: LLMClient, email: str, stats: ExtractionStats, max_repairs: int = 2
) -> ReturnRequest:
    messages = [{"role": "user", "content": f"<email>\n{email}\n</email>"}]
    schema = ReturnRequest.model_json_schema()
    for attempt in range(max_repairs + 1):
        resp = await client.complete(LLMRequest(
            model="fast",
            system=PROMPT.text,
            messages=messages,
            json_schema=schema,
            max_tokens=1024,
            metadata={"feature": "return_extraction",
                      "prompt_id": PROMPT.id, "prompt_version": PROMPT.version},
        ))
        stats.calls += 1
        # 1. reject MAX_TOKENS / REFUSAL stop reasons
        # 2. try ReturnRequest.model_validate_json(resp.text) -> return on success
        # 3. on ValidationError: count error types, append assistant output and
        #    a user message with json.dumps(exc.errors(include_url=False)), stats.repairs += 1
        ...
    stats.failures += 1
    raise ExtractionFailed(raw=resp.text, errors=[])
```
