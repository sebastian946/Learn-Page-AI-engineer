Every project in this course will land on your GitHub. Before you write the first line of LLM code, you set up the place that ties them together and the conventions they all follow. Think of it as the test framework you build before writing the first test: a little effort now saves you from inconsistency in seven repos later.

**Time:** 60–90 minutes.

## Goal

Create a public repo called `ai-engineer-portfolio` that contains:

1. A **hub README**: who you are, what you are targeting, and a projects table that you will fill in as you go.
2. A **reusable project README template** with the sections every project must have: Problem, Architecture, Evaluation, Cost & latency, Trade-offs, Run it, Limitations. Plus a demo GIF slot at the top.
3. A **`.github` pull request template** that asks for eval results and cost impact on every change.
4. A **conventions document** (`CONVENTIONS.md`): naming, branching, commits, folder layout, secrets, evals and README rules.
5. A small **README linter** (`scripts/check_readme.py`) that fails if a README is missing required sections, and a GitHub Actions workflow that runs it. You are an SDET: your conventions get an automated gate.

You will copy the template and PR template into every repo you create in Modules 1–7.

## Reference: CONVENTIONS.md outline

Use this as a starting point and adapt it. Keep it short; nobody reads a 20-page conventions doc.

```markdown
# Conventions

## Repo naming
kebab-case, describes the product not the tech: `support-ticket-router`, not `langchain-test-2`.

## Branches
main is always green. Work on `feat/<short-desc>`, `fix/<short-desc>`, `eval/<short-desc>`, `chore/<short-desc>`.

## Commits
Conventional Commits: feat, fix, docs, test, eval, refactor, chore, ci. Imperative, max 72 chars.
Example: `eval: add 20 golden questions for refinance policies`.

## Folder layout (Python projects)
src/<package>/   app code
tests/           unit + integration tests
evals/           datasets/, metrics, run_evals.py, results/
docs/            architecture.md, demo.gif, adr/
scripts/         one-off tools

## Secrets
Never commit keys. `.env` is gitignored; `.env.example` lists every variable with a fake value.
Model names and prices live in config, not in code.

## Evals
Every project has an eval dataset and a one-command eval run.
Any PR that changes prompts, retrieval or models must include before/after eval numbers.

## README contract
Every project README follows templates/PROJECT_README.md and passes scripts/check_readme.py.
```
