# Ejercicio: crea el repo hub de tu portafolio

Cada proyecto de este curso va a terminar en tu GitHub. Antes de escribir la primera línea de código con LLM, preparas el lugar que los une y las convenciones que todos siguen. Piénsalo como el framework de pruebas que construyes antes de escribir el primer test: un poco de esfuerzo ahora te evita inconsistencias en siete repos más adelante.

**Tiempo:** de 60 a 90 minutos.

## Objetivo

Crea un repo público llamado `ai-engineer-portfolio` que contenga:

1. Un **README hub**: quién eres, a qué apuntas y una tabla de proyectos que irás completando.
2. Una **plantilla reutilizable de README de proyecto** con las secciones que todo proyecto debe tener: Problem, Architecture, Evaluation, Cost & latency, Trade-offs, Run it, Limitations. Más un espacio para el GIF de demo al principio.
3. Una **plantilla de pull request en `.github`** que pida resultados de evals e impacto en costos en cada cambio.
4. Un **documento de convenciones** (`CONVENTIONS.md`): nombres, ramas, commits, estructura de carpetas, secretos, evals y reglas del README.
5. Un pequeño **linter de README** (`scripts/check_readme.py`) que falle si a un README le faltan secciones obligatorias, y un workflow de GitHub Actions que lo ejecute. Eres SDET: tus convenciones tienen un gate automático.

Vas a copiar la plantilla de README y la de PR en cada repo que crees en los Módulos 1 a 7.

<AcceptanceCriteria>

- [ ] Repo público en GitHub llamado `ai-engineer-portfolio` con una descripción corta y topics (por ejemplo `ai-engineering`, `llm`, `rag`, `portfolio`).
- [ ] `README.md` (hub) tiene: una introducción de un párrafo, una línea de "Target roles", una tabla de proyectos con las columnas Project, What it proves, Key result, Status, y un enlace a `CONVENTIONS.md`.
- [ ] `templates/PROJECT_README.md` contiene las secciones en este orden: título + pitch de una línea, GIF de demo, badge de CI, Problem, Architecture (con un bloque Mermaid), Evaluation (con una tabla de resultados), Cost & latency (con una tabla de costos y una fecha de "prices checked on"), Trade-offs & decisions, Run it, Limitations & next steps.
- [ ] `.github/pull_request_template.md` incluye: resumen, tipo de cambio, resultados de evals antes/después, impacto en costo/latencia, evidencia de pruebas y un checklist.
- [ ] `CONVENTIONS.md` cubre: nombres de repos, nombres de ramas, Conventional Commits, estructura estándar de carpetas, política de secretos, requisitos de evals y el contrato del README.
- [ ] `scripts/check_readme.py` termina con código 1 y lista las secciones faltantes cuando a un README le falta algún encabezado obligatorio; termina con 0 en caso contrario. Se ejecuta contra `templates/PROJECT_README.md` y pasa.
- [ ] `.github/workflows/readme-check.yml` ejecuta el script en cada push y PR, y la primera ejecución está en verde.
- [ ] Existen `.gitignore` y `templates/.env.example`; no hay secretos reales en ninguna parte del historial.
- [ ] Existe `LEARNING_LOG.md` con tu primera entrada de hoy.
- [ ] Al menos 4 commits con mensajes en formato Conventional Commits.

## Referencia: esquema de CONVENTIONS.md

Úsalo como punto de partida y adáptalo. Mantenlo corto; nadie lee un documento de convenciones de 20 páginas. Va en inglés porque lo leerán revisores del mercado objetivo.

```markdown
# Conventions

## Repo naming
kebab-case, describes the product not the tech: `support-ticket-router`, not `langchain-test-2`.

## Branches
main is always green. Work on `feat/<short-desc>`, `fix/<short-desc>`, `eval/<short-desc>`, `chore/<short-desc>`.

## Commits
Conventional Commits: feat, fix, docs, test, eval, refactor, chore, ci. Imperative, max 72 chars.
Example: `eval: add 20 golden questions for refinance policies`.

## Folder layout (Python projects)
src/<package>/   app code
tests/           unit + integration tests
evals/           datasets/, metrics, run_evals.py, results/
docs/            architecture.md, demo.gif, adr/
scripts/         one-off tools

## Secrets
Never commit keys. `.env` is gitignored; `.env.example` lists every variable with a fake value.
Model names and prices live in config, not in code.

## Evals
Every project has an eval dataset and a one-command eval run.
Any PR that changes prompts, retrieval or models must include before/after eval numbers.

## README contract
Every project README follows templates/PROJECT_README.md and passes scripts/check_readme.py.
```
