## Goal

Your Module 2 capstone, `mortgage-knowledge-assistant`, runs on your laptop with `uvicorn --reload` and a Postgres you started by hand. In this exercise you make it run anywhere with one command, in an image you would be comfortable shipping to production.

By the end you will have:

- A multi-stage `Dockerfile` built with uv, cache mounts, a slim base, a non-root user and a health check.
- A `docker-compose.yml` that starts the API, Postgres with pgvector, and Redis, with health-gated startup.
- A `.dockerignore` that keeps data, virtualenvs and `.env` files out of the build context.
- `/healthz` and `/readyz` endpoints.
- A measured image size and a short README section explaining the choices.

Work on a branch: `git switch -c m5/containerize`.

**Time box:** 75 minutes. If the re-ranker's `torch` dependency is making you fight the image, switch the re-ranker to a hosted API or disable it behind a setting for now, and write that down in the README as a conscious trade-off.

## Context

The service follows the layout from the previous lessons: `app/main.py` with a lifespan that opens the DB pool and Redis client, `app/settings.py` with pydantic-settings, `app/llm.py` with `LLM_PROVIDER=anthropic|mock`. If your Module 2 code differs, adapt it first: the containerization is much easier once config comes from environment variables only.

The mock provider is important here. With `LLM_PROVIDER=mock`, the whole stack runs locally with no API key and no cost. That is also how CI will run your container smoke test in a later exercise.

## Acceptance criteria

<AcceptanceCriteria>
- [ ] `docker compose up --build` starts `api`, `db` (image `pgvector/pgvector:pg16`) and `redis` with no manual steps, and the API waits for healthy `db` and `redis` before starting.
- [ ] The `Dockerfile` has at least two stages; the runtime stage contains no uv binary, no compiler and no package cache.
- [ ] Dependencies are installed from `uv.lock` with `--frozen`, in a layer that is not invalidated by changes under `app/`.
- [ ] BuildKit cache mounts are used for the uv cache; a rebuild after editing one Python file takes under 15 seconds on a warm cache.
- [ ] The container runs as a non-root user and uses exec-form `CMD` (uvicorn is PID 1).
- [ ] `GET /healthz` returns 200 without touching dependencies; `GET /readyz` returns 200 only when Postgres and Redis respond, and 503 otherwise.
- [ ] No secrets in the image: `docker history` and `docker inspect` show no API keys; `.env` is listed in `.dockerignore` and `.gitignore`; a `.env.example` is committed.
- [ ] Final image size is recorded in the README. Target: under 400 MB without a local model, under 1.2 GB with a CPU-only cross-encoder.
- [ ] With `LLM_PROVIDER=mock`, `curl -N -X POST localhost:8000/v1/chat/stream ...` streams `token` events followed by `citations` and `done`.
</AcceptanceCriteria>

## Hints

<Hints>
  <Hint>Build the dependency layer from bind mounts, not COPY. `RUN --mount=type=bind,source=uv.lock,target=uv.lock --mount=type=bind,source=pyproject.toml,target=pyproject.toml --mount=type=cache,target=/root/.cache/uv uv sync --frozen --no-install-project --no-dev`. Then `COPY app ./app` plus the two project files and run `uv sync --frozen --no-dev` again.</Hint>
  <Hint>For the readiness checks, wrap each probe in `asyncio.timeout(1)` and catch `Exception`, recording `"ok"` or `"fail"`. Use `await pool.fetchval("SELECT 1")` for asyncpg and `await redis.ping()` for redis-py. Never call the LLM provider from `/readyz`.</Hint>
  <Hint>Compose health checks: `test: ["CMD-SHELL", "pg_isready -U mka -d mka"]` and `test: ["CMD", "redis-cli", "ping"]`, both with `interval: 5s`, `retries: 10`. Your `infra/db/init.sql` should run `CREATE EXTENSION IF NOT EXISTS vector;` so the schema migration does not need superuser later.</Hint>
  <Hint>If the image is unexpectedly large, run `docker history mka:dev`. A huge layer from the sync step usually means CUDA `torch`: add the CPU index from lesson 02 to `pyproject.toml`, run `uv lock`, and rebuild. A huge `COPY` layer means your `.dockerignore` is missing `data/` or `.venv`.</Hint>
</Hints>
